# 深读：导读

这一层不是手册——手册在 [reference](../reference/)，跟着做在 [guide](../guide/)。
深读层回答的是「**为什么**」：每个设计背后被否决的选项、实测推翻过的直觉、
踩了三次才沉淀下来的坑。

## 三篇各自一段话

### [设计决策与理由](design.md)

**解决什么**：为什么插件是纯文本清单、为什么没有构建步骤、为什么 MCP annotations
不可信、为什么数据目录可以整个删掉——这些「看起来很奇怪」的决定，每一条都有
被否决的备选方案和当时的权衡。

**读完能做什么**：给别人讲清楚 zerokit 的设计哲学；在贡献新功能时判断
「这个能力该进内核还是该用清单表达」。

**适合谁读**：想给项目提 PR 的人、在纠结「要不要引入构建步骤/沙箱/包管理器」的
同类项目作者。

### 插件运行时（待写）

插件进程怎么拉起、UTF-8 编码怎么统一、常驻 host 为什么能把 476ms 压到 22ms。

### 安全边界（待写）

风险三级、MCP 授权、供应链快照、沙箱声明——四道防线各自的威胁模型。
（坑位，随下一轮补。）

## 怎么读

从上往下读一遍，遇到引用的源码文件就跳出去看一眼真身——文档里说的每个
结论都能在仓库里找到对应行，这也是 check-docs 校验的一部分。
