# web/app.js 拆分方案（第 241 轮预检，v4 清债第一轮）

> app.js 已 11273 行 / 249 个顶层函数——40+ 轮功能全堆一个文件。
> 直接拆会破坏 68 条 `app2.includes` 静态断言。本方案分五步，
> 每步只动一个功能域、断言同步改指向、全量绿后再走下一步。

## 依赖面（预检结论）

- webui-smoke 68 条 app2 断言，落点 Top：showServices(8) / showPalette(7) /
  showWatchPanel(6) / renderDevPanel(5) / runBatch(5) / openDetail(3) / renderLogs(3)

  app.js import 且文本留在 web/ 目录任一 .js 里，改为读新文件即可。

### 三次判据升级

1. **注入式拆分**（241 试点确立）：直接 import 循环依赖 → createXxx(ui) 工厂 + 惰性 getter。
2. **迭代验证式提取**（243 确立）：每删一个函数立即 node --check——自动拦截删除伤邻居与内部物误判。
3. **整域内聚**（245 确立）+ **多变量状态桥接**（247 确立）：域内互调不进注入表；面板 let 状态经 get/set 桥。

### 遗留与后续

## 补篇：三层防线（第 254 轮，2026-11-11）

251-253 轮把「拆分后怎么验收」沉淀为三层防线。本篇是完整体系——v4 及任何大型重构的验收模板。

### 职责矩阵

| 层 | 建立轮 | 查什么 | 天然漏什么 | 为什么需要下一层 |
|---|---|---|---|---|
| **L1 静态断言**（test/\*-smoke，3155 条） | 各功能轮 | 文本存在于正确文件（函数体/接线/样式） | 文本在但**绑定不在**——242 轮插入事故后 getter 块嵌套坍塌，文本全在、顶层作用域全无，九轮全绿带病发布 | 存在性 ≠ 可达性 |
| **L2 注入面契约**（domain-faces-smoke，18 条） | 253 | 双侧键集一致：域文件解构 ⊆ app 注入；跨域引用有注入依据 | 两侧一致但**语义错**（键对得上、值形态不对——函数期待 ref 却传了裸值） | 结构约定 ≠ 行为正确 |
| **L3 CDP 运行时**（cdp-smoke，3 条） | 251 手工 → 252 进 CI | 真实浏览器逐面板零 console error——绑定、注入、语义全在实际执行中验证 | 无显示环境（skip 兜底）；瞬时竞态需 --version 探测加固 | — |

### 各层抓出的真缺陷

- **L3 抓出（251 轮，26 处）**：getter 块嵌套坍塌（根因一：242 轮插入吞掉后续 7 个 getter 声明）+ 20 处注入面漏配（mode/$/el/readJson/...）。L1 全绿九轮没发现。
- **L2 抓出（253 轮，1 处）**：market 的 exitMarket 解构未注入——251 轮手工修复时的漏网之鱼，L3 当轮也没触发到那个按钮路径。
- **L1 的不可替代性**：L2/L3 都不查文案/样式/交互细节——三行/秒级回归仍然只有静态断言覆盖得住。

### 通用化：非拆分类重构怎么套

1. **有「双侧约定」的改动**（接口/事件/存储键）→ 套 L2：把约定写成键集断言。
2. **有「组合爆炸」的运行路径**（面板×状态×交互）→ 套 L3：挑最高频路径做逐项打开零错误。
3. **其余** → L1 够用，但记住它的盲区：**存在性断言永远不能证明可达性**。

### 一句话判据

> 静态断言查文本、契约查结构、运行时查行为——三层各司其职，缺一层就有一类缺陷能带病通过前两层。
