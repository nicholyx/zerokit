# 设计决策与理由

这份文档记录**为什么这么设计**。代码能告诉你做了什么，但看不出被否决的选项和背后的权衡。

## 支点：一份清单，多个面

最初的诉求是"让插件能被 AI 调用"。几乎所有同类项目的做法是：先做插件体系，再补一个
MCP 适配层。这条路的问题是把「给 AI 用」变成了第二套开发工作，生态里只有少数插件会做。

zerokit 反过来：**插件只声明能力、参数、风险，各端从同一份声明自动派生**。

```
plugin.toml ──┬── 参数投影 ──→ JSON Schema  ──→ MCP 工具 inputSchema
              │            ──→ CLI flag      ──→ zkit run --参数
              │            ──→ 表单字段       ──→ 启动器 / Web 表单
              ├── 名字派生 ──→ {id}__{action} ──→ MCP 工具名
              ├── 风险派生 ──→ 确认策略        ──→ 界面确认弹层 / MCP annotations
              └── run 数组 ──→ argv           ──→ 子进程直接执行
```

代价是清单要比"只有个入口脚本"复杂一些；收益是**加一个参数，四个面同时多出来**。

## 同类项目调研给我们的三个结论

调研覆盖了 uTools、Flow Launcher、PowerToys Run、Keypirinha、Wox 2、Raycast、Alfred，
以及 MCP 规范原文。

### 1. 「插件化」本身不是差异点，绑定宿主才是问题

uTools 的锁定点**不在它的 API**——`utools.*` 里几乎每个方法都是 Electron 的一两行封装，
复刻难度极低。真正的护城河是四件事：OS 级能力（全局热键、读当前活动窗口、
模拟键鼠、粘贴进任意前台窗口）、`preload.js` 直通 Node、每插件一个独立进程、
以及生态惯性（私有 `.UPXS` 包 + 中心化审核）。

我们的应对不是复刻 API，而是**让插件不绑定任何宿主**：插件是纯文本清单，
内核无 UI 依赖，所以同一份插件能跑在 CLI、启动器、以及任何 MCP 客户端里。

> 顺带一个战略选项（尚未做）：uTools 的 `features[].cmds` 结构设计得很干净
> （字符串关键字自动支持拼音首字母、`regex`、`over`、`img`、`files`、`window` 六型），
> 而且形态是从 `main` 是否存在 + preload 挂什么推导的。做一套 `utools.*` 兼容 shim
> 就能吃到存量插件生态——这比重新发明一套 API 有价值得多。

### 2. 运行模型抄 Wox 2，不抄 PowerToys Run

| 项目 | 插件运行模型 | 判断 |
|---|---|---|
| Flow Launcher / PowerToys Run | 同进程加载 DLL（一个插件崩 = 全崩） | ❌ 不抄 |
| Keypirinha | C++ 内嵌 CPython，同进程 | ❌ |
| **Wox 2** | 单进程核心 + 插件独立 host 子进程 + JSON-RPC，host 崩了可单独重启 | ✅ 抄 |

我们目前更保守：**每次调用起一个进程**。好处是隔离最彻底、实现最简单；
坏处是冷启动会拖慢启动器的体感（把 50ms 变成 5s）。常驻 host 是下一步要做的。

### 3. 只有 Raycast 把「能力类型」写进了清单

其余项目都是"运行时返回结果对象"，清单里没有能力类型字段。要表达"这个插件带 UI、
那个是 headless、还有一个常驻后台"，就得学 Raycast 把 `mode` 写进 manifest。
这一条我们还没做。

## 安全：三个不能省的判断

### 风险等级必填，不是装饰

调研里最有用的一句：**副作用常常超出接口名所示**——"查询订单"内部可能带消息推送、
下载链接生成、日志写入。所以 `risk` 是必填字段，作者必须显式权衡；
它同时驱动 UI 的确认策略和 MCP 的 `readOnlyHint` / `destructiveHint` 标注。

### MCP 面的默认拒绝

MCP 规范明确要求客户端**必须把 annotations 当作不可信**。这意味着不能指望
AI 客户端替我们把关。所以：

- 只读动作默认放行
- 有副作用的动作必须先在终端 `zkit mcp allow <插件>.<动作>` 显式授权一次
- 被拒时返回一条**给模型看的**说明（"请让用户执行 zkit mcp allow …"），
  而不是一句干巴巴的报错

同时 `annotations` 仍然如实标注——诚实标注 + 不依赖它，两件事不冲突。

### 确认令牌绑定参数

界面上的确认流程里，第一次请求返回 `needConfirm` 和**解析后的完整命令**，
以及一个 HMAC 令牌。令牌是 `HMAC(secret, 插件|动作|JSON(参数))`。
用户确认后带着令牌重发，服务端重算比对。

这样杜绝了"用户看到并确认的是 A，实际执行的是 B"——**换一组参数，令牌就失效**。

## 界面：启动器与工作台是同一个窗口的两种模式

调研点出了一对真实矛盾：启动器要求**毫秒级、一击即中、结果确定**；
工作台是**意图模糊、多轮、秒到分钟**。同一个输入框，用户分不清这句会被当命令执行
还是当任务规划。三条对策：

1. **显式模式切换**：以 `?` 开头进工作台，让用户按下回车之前就预知走向。
2. **可视化工具调用**：只读动作也**必须**显示卡片。早期版本只在"需要审批"时创建卡片，
   结果模型在后台悄悄调了工具，用户完全看不见——这个是靠截图才发现的。
3. **确认框给完整命令**，不是动作名。看到什么就是跑什么。

## 工作台：吃自己的狗粮

工作台把插件动作当工具跑 agent 循环，用的是**和 MCP 面完全相同的插件清单**。
所以工作台里能用的工具，和 Claude Code / Cursor 里能用的必然一致——
这让"一个面能用但另一个面不能用"这类不一致无处藏身。

模型层做了 provider 抽象，agent 循环不依赖任何厂商：

| provider | 实现要点 |
|---|---|
| `anthropic` | 官方 SDK。Opus 5.5 上**不能强制 tool_choice**（用 `auto` + `strict: true`）、**thinking 不能禁用**（用 adaptive + `output_config.effort`）、`tool_result` 必须全部放在同一条 user 消息里（拆开会让模型不再并行调用工具）。带了服务端 fallbacks，服务端不认时自动降级重试一次 |
| `openai` | 任何 OpenAI 兼容端点走原始 HTTP。流式工具调用是**碎片到达**的，必须按 index 累积后再解析 |
| `mock` | 不联网的假模型，用于零成本跑通整条链路与自测 |

## 跨平台踩坑沉淀

这些是实际跑出来的，不是查文档查来的：

- **Windows 上 `python.exe` 可能只是微软商店的占位程序**，跑起来只会弹商店。
  所以依赖定位会跳过 `WindowsApps` 目录、并且**实际执行 `--version` 验证**才算数。
- **Python 往管道写默认用系统代码页**（中文机器是 GBK），按 UTF-8 解码就是乱码。
  对 python 解释器自动注入 `PYTHONIOENCODING=utf-8`；其它语言用 `encoding` 声明。
- **按数据块 `toString()` 解码会切坏跨块的多字节字符**，必须用 `StringDecoder`。
- **MCP 的 stdio 模式 stdout 只能是 JSON-RPC**，混一行日志就握手失败。
- **stdio server 不能提前 return**，否则调用方的 `process.exit` 会把它当场杀掉，
  客户端永远等不到 `initialize` 的响应。

## 分发与信任

- **集市 = 一个 git 仓库 + 根目录一个 `market.json`**。没有中心服务、没有账号、没有审核。
  成本极低，谁都能开一个。
- **安装前必须摊开审查**：把该插件的全部动作、真实命令、风险等级列出来让人确认。
  非交互环境不给 `--yes` 直接拒绝（往安全的一侧倒）。
- **存安装时的清单快照**，之后被改动可以发现（对应 rug pull 风险）。
- **不假装是沙箱**：白名单只管得住直接启动的程序名，管不住它自己 spawn 的子进程、
  读的配置文件、发起的网络请求。真实隔离只能靠 OS 级方案（容器 / 低权限用户 / 只读挂载）。
  这句话是照抄 `tumf/mcp-shell-server` 的诚实措辞，我们认同这个立场。

## 明确没做的事

- **没有中心账号体系**。同步走用户自己的存储（这条还没实现，但方向是不回到中心化）。
- **没有插件数量上限**。uTools 免费版只能装 10 个插件，这是它存在的理由反而不是我们的。
- **没有做 OS 级沙箱**。见上。
- **没有做拼音匹配**。这是 uTools 的真实护城河（中文用户打 `dl` 能出"代理"），
  但需要引入一个拼音表。目前用 `keywords` 让插件作者手工声明缩写来绕过。
